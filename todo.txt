// CONFIG — valores hardcodeados HOY que deben vivir en un struct Config
//
// OBJETIVO: crear src/config.rs con un struct Config cargado desde
// $XDG_CONFIG_HOME/vinland/config.toml (fallback ~/.config/vinland/config.toml)
// Los valores de Config deben poder recargarse en caliente (SIGHUP o inotify).
// Crates recomendados: serde + toml + notify (para inotify hot-reload)
//
// REFERENCIA RÁPIDA DE HARDCODES EN EL CÓDIGO HOY:
//   src/state.rs:
//     const GAP: i32 = 8                   -> Config.tiling.gap
//     refresh: 144_000                      -> Config.output.refresh_rate
//     "vinland-output"                      -> Config.output.name
//     XkbConfig::default()                  -> Config.keyboard.xkb
//     repeat delay 200, repeat rate 25      -> Config.keyboard.repeat_delay/rate
//     (0,0) output position                 -> Config.output.position
//     w/2 master split ratio                -> Config.tiling.master_ratio
//     layout siempre MasterStack            -> Config.tiling.layout
//   src/render.rs:
//     [0.0, 0.0, 0.0, 1.0] fondo negro     -> Config.background.color / wallpaper
//     damage siempre pantalla entera        -> damage tracking real
//   src/handlers/xdg_shell.rs:
//     dialog_w = 600, dialog_h = 500        -> Config.floating.default_dialog_size (x2)
//     diálogos siempre al centro            -> Config.floating.default_position
//   src/main.rs:
//     tracing_subscriber::fmt::init()       -> Config.log.level
// ==============================================================================

[TILING]
- GAP: i32 = 8
  * const GAP en state.rs
  * separar en Config.tiling.gap_inner (entre ventanas) y Config.tiling.gap_outer (borde)

  // mayoritariamente hardcodeado.

- numero de columnas
  * siempre 2 por defecto

- layout por defecto
  * siempre MasterStack, no cambiable sin recompilar
  * Config.tiling.layout: enum { MasterStack, Monocle, Columns, Spiral, ... }

- split ratio master/stack
  * hardcodeado como w/2 en retile()
  * Config.tiling.master_ratio: f32 (default 0.5)

- número de masters
  * siempre 1
  * Config.tiling.master_count: u32 (default 1)



[VENTANAS FLOTANTES]
- tamaño por defecto de diálogos (ventanas con padre)
  * xdg_shell.rs: dialog_w = 600, dialog_h = 500 (hardcodeado 2 veces: new_toplevel y parent_changed)
  * Config.floating.default_dialog_size: (u32, u32)

- posicion general:
  * hoy por defecto al centro.
  * Config.floating.default_position: (u32, u32)
  // u32 = cualquier numero entero positivo
  // para usarlo en posiciones de pixeles en la pantalla.
  // "u32" (unsigned integer 32 bits) se usa comunmente para
  // representar coordenadas (x, y), tamaños (width, height), o conteos de pixeles
  // en pantallas y graficos, ya que no puede ser negativo.

- reglas por clase de ventana (window rules)
  * ninguna ventana puede ser forzada a flotar o a un tamaño fijo desde config
  * Config.rules: Vec<WindowRule>
    WindowRule { app_id: String, title_regex: Option<String>, action: RuleAction }
    RuleAction: Float | Tile | FloatSize(w,h) | Workspace(u8) | Opacity(f32) | ...

[WORKSPACES / ESCRITORIOS VIRTUALES]
- hoy todas las ventanas viven en un único espacio plano
- agregar Vec<Workspace> al state, cada Workspace con su Vec<Window>
- Config.workspaces.count: u32 (default 9)
- Config.workspaces.layout: puede ser diferente por workspace
- transición al cambiar workspace: animación slide/fade
- protocolo ext-workspace-v1 para que paneles lo consulten

[SCREENSHOT / SCREENCAST]
- zwlr_screencopy_manager_v1
  * permite a grim, slurp, obs capturar el framebuffer
  * smithay tiene screencopy support (feature "wayland_frontend")
- xdg-desktop-portal screencast
  * para Firefox/Chrome compartir pantalla por WebRTC

[IDLE / DPMS]
- ext-idle-notify-v1 (smithay tiene ExtIdleNotifierState)
  * avisar a apps (swayidle) cuando usuario está idle N segundos
  * Config.idle.timeout_sec: u32
- DPMS: apagar el output cuando idle
  * DRM: deshabilitar CRTC; Winit: no aplica directamente

[INPUT METHODS / IME]
- protocolo zwp_text_input_v3
  * para teclados en pantalla y métodos de entrada (fcitx5, ibus)
  * smithay: TextInputManagerState

[TABLET / STYLUS]
- protocolo zwp_tablet_manager_v2
  * tabletas gráficas (Wacom, Huion, XP-Pen)
  * smithay: TabletManagerState

[WLROOTS LAYER SHELL] (CRÍTICO PARA EL DE)
- protocolo zwlr_layer_shell_v1
  * NECESARIO para: bars, docks, notificaciones, fondos propios
  * layers: Background, Bottom, Top, Overlay
  * smithay: WlrLayerShellState + WlrLayerShellHandler
  * hay que agregar layer surfaces al render loop, ordenadas por layer
  * z-order: Background < Bottom < tiled windows < floating < Top < Overlay

[OUTPUT MANAGEMENT]
- zwlr_output_manager_v1 (wlr-output-management)
  * kanshi, wlr-randr pueden configurar outputs en runtime
  * cambiar resolución, posición, escala, rotación sin reiniciar

[XWAYLAND] (ya en Cargo.toml como feature)
- smithay tiene XWayland support completo
- inicializar XWayland en state.rs, agregar XWayland surfaces al render
- Config.xwayland.enabled: bool (default true)
- Config.xwayland.scale_factor: Option<f64> (override para apps X11)
- necesario para: Steam, Wine, algunas Electron apps antiguas

[FRACTIONAL SCALING / HIGH DPI]
- smithay soporta Scale::Fractional
- protocolo wp_fractional_scale_v1 para que apps ajusten su resolución
- Config.output.scale: f64 (1.0, 1.25, 1.5, 2.0, etc.)

[PRESENTATION TIME]
- protocolo wp_presentation (smithay: PresentationState)
  * video players saben exactamente cuándo su frame fue mostrado
  * necesario para low-latency video playback sincronizado

[VIEWPORTER]
- protocolo wp_viewporter (smithay: ViewporterState)
  * scaling y cropping de buffers en el compositor
  * necesario para HiDPI y video players

[LINUX DMABUF] (crítico para performance)
- protocolo zwp_linux_dmabuf_v1 (smithay: DmabufState)
  * zero-copy buffer sharing GPU <-> apps
  * sin esto: copia extra del framebuffer por frame en Firefox, Chromium, etc.
  * Cargo.toml ya tiene "backend_drm" -> DmabufState necesita GBM allocator
  * en winit backend: limitado; en DRM backend: necesario y muy importante

[COLOR MANAGEMENT / HDR]
- protocolo xx_color_manager_v4 / wp_color_management_v1 (draft)
  * HDR, wide color gamut
  * smithay está agregando soporte
  * FUTURO, no urgente

[SECURITY CONTEXT]
- protocolo wp_security_context_v1
  * sandboxed clients (flatpak, snap) presentan credentials al compositor
  * el compositor decide qué protocolos exponer según sandbox level

// ARCH — refactors estructurales necesarios

[CONFIG SYSTEM]
- crear src/config.rs con struct Config completo
- cargarlo desde TOML con serde + toml crates
- ruta: $XDG_CONFIG_HOME/vinland/config.toml
- hot-reload con notify crate (inotify): suscribirse a cambios del archivo,
  aplicar campos que se puedan cambiar en caliente sin reiniciar

[BACKEND ABSTRACTO]
- hoy fijo a WinitGraphicsBackend<GlesRenderer>
- para hardware real se necesita DRM/KMS (smithay UdevBackend)
- extraer trait Backend { ... } o enum WinitBackend | DrmBackend
- Cargo.toml ya tiene "backend_drm" y "backend_udev"
- UdevBackend loop: detectar GPU con udev, abrir DRM device, GbmAllocator,
  EglDisplay sobre GBM, GlesRenderer

[RENDER PIPELINE]
- mover lógica de render a un struct Renderer propio
- abstraer el "frame" para facilitar damage tracking real
- separar: collect_elements() | clear_background() | draw_layer(Background) |
  draw_layer(Bottom) | draw_windows() | draw_layer(Top) | draw_cursor() | draw_layer(Overlay)
- considerar smithay::desktop::Space para z-ordering y damage automático

[WINDOW TREE]
- hoy windows: Vec<Window> es un vec plano sin jerarquía
- con layer shell, popups y xwayland se necesita estructura jerárquica:
  Vec<LayerSurface> + Vec<Window> + Vec<XwaylandSurface>
  o usar smithay::desktop::Space (maneja z-ordering, damage, surface tree)

[LOGGING]
- hoy: tracing_subscriber::fmt::init() solo stdout
- agregar file logging: tracing-appender hacia ~/.local/share/vinland/vinland.log
- log rotation (tracing-appender::rolling)
- Config.log.level: enum { Error, Warn, Info, Debug, Trace }

[IPC]
- mecanismo para que el DE (barras, lanzadores) hable con el compositor
- preferir Unix socket + JSON (similar a sway IPC, sin depender de D-Bus)
- mensajes básicos:
    list_windows -> [{app_id, title, workspace, focused, rect}]
    focus_window(id)
    close_window(id)
    move_to_workspace(id, ws)
    get_config -> JSON del Config actual
    reload_config
    screenshot(output) -> bytes
    subscribe(event_type) -> stream de eventos
